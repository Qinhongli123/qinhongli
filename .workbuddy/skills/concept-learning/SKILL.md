# 个人概念学习资料生成 Skill（concept-learning）

## 一、适用场景

本 Skill 适用于以下情况：

1. **零基础入门新领域**：遇到一个完全陌生的概念（例如本作业中的 Agent、大模型上下文、Skill），需要一份"从零讲起"的系统资料，而不是零散的百科词条；
2. **课程作业/小组汇报前的快速学习**：需要在短时间内把一个概念讲到"能给别人讲明白"的程度；
3. **复习与自测**：资料内置自测问题和可折叠的参考答案，适合考前复习或检验理解程度；
4. **跨专业学习**：生成资料时会刻意结合使用者自己的专业背景（如广告学）举例子，让抽象概念落地。

## 二、输入信息

调用本 Skill 时，需要提供以下信息：

| 输入项 | 是否必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `concept` | 必填 | 要学习的目标概念 | `Agent` / `大模型的上下文` / `Skill` |
| `background` | 选填 | 使用者的专业背景，用于生成贴近其专业的案例 | `广告学大二学生` |
| `depth` | 选填 | 资料深度：`入门`（默认）/ `进阶` | `入门` |
| `output_format` | 选填 | 输出格式，默认 `html`，可选 `markdown` | `html` |

调用示例（自然语言）：

> 请用 concept-learning Skill 帮我生成"Agent"的学习资料，我是广告学大二学生，入门深度，输出 HTML。

## 三、生成步骤

Skill 收到输入后，按以下六步生成资料：

1. **概念界定**：从权威来源（官方文档、经典论文、教科书）交叉确认概念的定义，用一句大白话 + 一句规范定义双轨呈现，避免"用一个术语解释另一个术语"；
2. **机制拆解**：把概念的底层原理拆成 3~5 个可理解的机制模块，每个模块配简短说明；
3. **案例生成**：结合使用者的专业背景，生成 1~2 个具体应用案例（广告学背景优先选用广告投放、品牌营销、社媒运营等场景）；
4. **概念辨析**：找出最容易与目标概念混淆的 2~3 个近邻概念，用对比表格说明区别；
5. **自测出题**：围绕"定义、机制、应用、辨析"各出至少 1 道自测题，附参考答案（默认折叠）；
6. **来源标注**：整理本次资料参考的来源清单（官方文档、论文、技术博客），供延伸阅读与溯源核查。

## 四、输出结构

生成的学习资料为 HTML 页面（内联样式、无外部依赖、离线可看），页面结构固定为六个模块：

```
┌────────────────────────────────────┐
│  页头：概念名 + 一句话定义 + 导航    │
├────────────────────────────────────┤
│  1. 概念定义（大白话 + 规范定义）    │
│  2. 核心机制（3~5 个模块拆解）      │
│  3. 应用案例（结合专业背景）        │
│  4. 概念辨析（与近邻概念对比表）    │
│  5. 自测问题（折叠式参考答案）      │
│  6. 参考来源（可溯源的资料清单）    │
└────────────────────────────────────┘
```

对应的文件存放结构：

```
.workbuddy/skills/concept-learning/
├── SKILL.md                     # 本文件：Skill 的元信息与使用说明
├── README.md                    # Skill 使用说明（面向人的快速上手文档）
├── concept-relationship.html    # 本次三个学习概念之间的关系图与个人理解
└── training-materials/          # 概念学习资料（Skill 的输出成果）
    ├── agent.html               # 概念一：Agent
    ├── llm-context.html         # 概念二：大模型的上下文
    └── skill.html               # 概念三：Skill
```

## 五、资料来源

本 Skill 生成资料时优先参考以下类型的来源，并在每个概念页面末尾标注具体清单：

1. **官方一手文档**：如 Anthropic《Building Effective Agents》、OpenAI 平台文档、Claude / CodeBuddy 的 Agent Skills 官方说明；
2. **经典论文**：如 *Lost in the Middle: How Language Models Use Long Contexts*（Liu et al., 2023）；
3. **高质量技术博客**：如 Lilian Weng（OpenAI 研究员）的 *LLM Powered Autonomous Agents*；
4. **交叉验证**：同一结论至少核对两个独立来源，不一致时在资料中明确标注争议点。

## 六、自检要求

每次生成资料后，Skill 须按以下清单自检，不满足则重新生成：

- [ ] 定义部分是否同时包含"大白话解释"和"规范定义"？
- [ ] 核心机制是否拆解为 3~5 个模块，且每个模块都能被零基础读者看懂？
- [ ] 应用案例是否结合了使用者的专业背景（广告学）？
- [ ] 概念辨析是否至少对比了 2 个易混淆概念，并说明了关键区别？
- [ ] 自测问题是否覆盖"定义 / 机制 / 应用 / 辨析"四个维度？
- [ ] 参考来源是否真实可查、可溯源？
- [ ] 页面是否无外部依赖、离线可正常打开？
- [ ] 资料中是否不含任何个人隐私、密钥或敏感信息？
