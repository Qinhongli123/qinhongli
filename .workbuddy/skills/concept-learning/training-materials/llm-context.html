大模型的上下文（Context）

一句话理解：模型一次回答时能"看到"的全部信息及其容量上限，相当于它的"工作记忆"——窗口就这么大，塞满了旧的就记不住新的。

🏠 概念关系图 · Agent · 大模型的上下文 · Skill

1概念定义

大白话版：把大模型想象成一个每次考试都"失忆"的学霸：不管多聪明，它只能看着这次考卷上写了什么来答题。这张"考卷"就是上下文——你发的消息、之前聊过的内容、喂给它的资料，全都算；而考卷的页数是有上限的，这个上限叫"上下文窗口"。
规范定义：上下文（Context）指大模型在进行一次推理（生成回答）时，作为输入条件提供给模型的全部 token 序列，包括系统提示词、历史对话、检索到的资料与当前提问；上下文窗口（Context Window）是模型单次推理所能处理的最大 token 数量。窗口内的信息模型都能"注意到"，超出窗口的信息则完全不可见。

2核心机制

✂️ Token：计量的单位

模型不按"字"也不按"词"读文本，而是按 token（词元）切分。经验值：中文 1 个汉字 ≈ 1~2 个 token，英文 1 个单词 ≈ 1.3 个 token。窗口大小、API 计费都以 token 计。

🪟 窗口：有限的注意力

主流模型窗口从 8K 到 200K 甚至 1M token 不等。1 个 token≈0.75 个英文单词，100K token 大约相当于一本 15 万字的中文书。窗口越大，一次能"带着读"的资料越多。

👀 注意力：不是雨露均沾

窗口内的信息也并非被同等对待。研究发现模型对开头和结尾的内容最敏感，中间部分容易被忽略，即"Lost in the Middle"现象——重要内容要放在两头。

🧩 上下文内学习

不改模型参数、不重新训练，只在上下文里放几个示例（few-shot），模型就能模仿格式和风格完成任务。"现学现卖"全靠上下文。

一次对话中上下文的占用示意（窗口 128K）：
系统提示 3%
上传的品牌资料 24%
历史对话 16%
当前提问 8%
剩余 ≈49% 留给模型生成回答；对话越长、资料越多，剩余空间越小，早期内容可能被挤出窗口。

3应用案例（广告学视角）

案例：把"品牌手册"装进上下文写文案
为某茶饮品牌写小红书种草文案时，把品牌手册（品牌故事、slogan、禁用词、目标人群画像、过往爆款笔记）共约 2 万字全部放进上下文，再下达指令。模型写出的文案会自动对齐品牌调性、避开禁用词、延续爆款句式——这些"知识"全部来自上下文而非模型训练记忆。
案例：长文档Brief 一键拆解
客户发来 60 页的年度营销 Brief（约 8 万 token）。长上下文模型可以一次性读完全文，直接输出"目标人群、核心诉求、预算分配、KPI、时间节点"五张摘要卡。若用小窗口模型，只能分段投喂，模型看不到全局，拆解质量明显下降。
踩坑提醒："新开一个对话"意味着上下文清零——上个对话里喂过的资料、聊过的结论，新对话里模型一概不知。跨对话想让 AI"记得你"，靠的是产品的长期记忆功能（把摘要存下来、下次自动注入上下文），而不是模型自己记住。

4概念辨析：三个容易混淆的"记忆"

对比维度训练知识（参数记忆）上下文（工作记忆）长期记忆（外部存储）
存哪模型参数内部，训练时固化当前这次推理的输入窗口模型外的数据库/文件
能改吗不能（除非重新训练/微调）能，随每次对话动态变化能，随时增删
时效性止于训练截止日完全实时取决于写入的内容
跨对话天然跨对话不跨，对话结束即消失跨，需检索后再注入上下文
广告类比文案老手的"功力"摆在桌上的那份 Brief档案柜里的客户资料

5自测问题（点击展开参考答案）

Q1：为什么 AI 经常"聊着聊着就忘了"前面说过的内容？
因为对话历史也是上下文的一部分，会不断累积占用窗口。当总 token 数逼近窗口上限时，较早的内容会被截断或压缩出窗，模型自然"失忆"。解决办法：开新对话并重新提供关键信息，或主动让模型先输出一份摘要供后续使用。
Q2：上下文窗口 128K 的"K"是什么单位？大概能装多少内容？
K = 1024。128K ≈ 13 万 token；对中文而言大约相当于 6~10 万汉字（1 汉字 ≈ 1~2 token），约等于一本中等厚度的书。
Q3：给模型喂一份长资料时，最关键的信息应该放在开头还是中间？为什么？
放在开头或结尾，避免中间。根据《Lost in the Middle》论文的实验，模型对序列首尾位置信息的利用率显著高于中部——同样一份品牌手册，把核心卖点放在最前面，模型遵循得最好。
Q4：模型知道了"昨天刚发布的明星代言新闻"，这是通过上下文还是训练知识实现的？
上下文。训练知识止于模型训练截止日期，不可能包含"昨天"的信息；一定是 Agent 通过联网搜索工具把新闻抓回来、放进上下文，模型才"知道"。这也是工具调用与上下文配合的典型场景。
