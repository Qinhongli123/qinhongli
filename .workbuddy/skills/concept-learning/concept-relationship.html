Agent × 大模型上下文 × Skill

三个概念如何配合，让 AI 从"会说话"变成"会做事"

🏠 概念关系图 · Agent · 大模型的上下文 · Skill

一、三个概念的一句话回顾

🤖 Agent（智能体）

回答"谁来做"——以大模型为大脑、自主规划并调用工具完成目标的执行者。

🪟 大模型上下文

回答"它此刻知道什么"——一次推理中模型能看到的全部信息，容量有限的"工作记忆"。

📦 Skill（技能包）

回答"它会哪些本事"——用结构化文件描述、按需加载的成套能力与方法。

二、关系图：一次任务的完整旅程

读图要点：① 用户只给目标，中间过程由 Agent 自主完成；② Agent 每一步推理都离不开上下文（读出已知信息、写入中间结果）；③ Skill 平时不占地方，命中场景才把"成套方法"注入上下文；④ Skill 中描述的流程还会指挥 Agent 去调用外部工具。

三、我的类比理解：一个广告公司里的策划总监

作为广告学学生，我把这三个概念类比成一位广告公司的策划总监接下一个 brief 的全过程：

执行者

Agent = 策划总监

接到客户 brief 后不等人催，自己拆解任务（先调研、再定位、后创意）、安排执行、检查质量、迭代修改，最终交出完整方案。他不是"答一句算一句"的客服，而是对最终交付负责的人。

工作记忆

上下文 = 他此刻的办公桌面

桌面上摊开着 brief、调研数据、品牌手册、和客户的聊天记录——他此刻能参考的一切。桌面面积有限（窗口上限）：摊不下就撤走旧的；下班清桌（新开对话），第二天他不会记得昨天摊开过什么。

方法论

Skill = 他熟练掌握的 SOP 手册

公司沉淀的《竞品分析方法论》《提案 PPT 规范》《舆情监测流程》。平时锁在文件柜里不占桌面（不占上下文）；接到对应任务时抽出来放在桌面上照着执行（按需加载）——手册还会告诉他该用哪些软件和数据库（调用工具）。

一句话总结：Agent 是做事的人，上下文 是他此刻眼前的资料，Skill 是他抽屉里的成套方法——人 + 桌面 + 手册，缺一样都干不好活。

四、综合案例：一个任务同时用到三者

任务："帮我为新品咖啡做一个上市传播方案。"

① 目标进入 用户把目标（可能还有品牌资料）发给 Agent——这些内容进入上下文，成为 Agent 眼前的"桌面资料"。

② Agent 规划 Agent（策划总监）拆解任务：市场调研 → 竞品分析 → 人群洞察 → 传播策略 → 渠道规划 → 预算分配。每一步的中间结论都会写回上下文，供后续步骤参考。

③ 命中 Skill 当进行到"竞品分析"时，平台发现已安装「竞品分析方法论 Skill」适用，自动把该 Skill 的 SKILL.md 注入上下文——Agent 瞬间"学会"了标准分析框架，不用用户现场教。

④ 调用工具 按 Skill 的指引，Agent 依次调用搜索工具抓取竞品近 30 天的社媒声量、调用表格工具整理数据、调用代码工具画趋势图——每一步的执行结果同样回填上下文。

⑤ 反馈迭代 Agent 检查产出：发现某个渠道的数据缺了两天，自动回到第④步重新抓取补齐（反馈循环）。

⑥ 交付成果 最终输出完整传播方案。若对话继续，上下文持续累积；一旦用户新开对话，桌面清空——想延续，就靠长期记忆功能把摘要"重新摊回桌面"。

五、三个常见误区澄清

误区澄清
"上下文窗口大 = AI 记性好，能永远记住我"窗口再大也只是这一次任务的工作记忆；跨对话的"记住"靠外部长期记忆机制，与窗口大小无关。
"装了 Skill，Agent 就变聪明了"Skill 不改变模型智力，它提供的是成套的方法与流程——让同样的聪明用在正确的轨道上，产出更稳定。
"Skill 就是提前写好的提示词"提示词是"每次手动贴的便签"；Skill 由平台自动识别场景、按需加载，还能包含流程、自检清单与附属资源，是"制度"而非"便签"。
