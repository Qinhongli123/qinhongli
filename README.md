## 一、这个仓库是什么？

这是我的 Python 课程作业仓库。本次作业的任务是：**用 AI 构建一个"个人概念学习资料生成 Skill"**，并借助 GitHub 进行版本管理。

整个项目围绕三个 AI 领域的核心概念展开学习，并把学习成果制作成了可以直接在浏览器中打开的 HTML 学习资料页：

| 概念 | 一句话理解 |
| --- | --- |
| **Agent** | 以大模型为"大脑"、能自主规划并调用工具完成任务的 AI 系统 |
| **大模型的上下文** | 模型一次推理能"看到"的信息范围，相当于它的"工作记忆" |
| **Skill** | 用声明式文件描述、可被 AI 按需加载调用的"能力包" |

## 三、怎么使用这些资料？

1. **看概念关系**：先打开 `.workbuddy/skills/concept-learning/concept-relationship.html`，了解三个概念如何互相配合（这是我最推荐先看的一页）；
2. **逐个学习**：再依次打开 `training-materials/` 里的三个 HTML 页面，每页都包含：概念定义 → 核心机制 → 应用案例 → 概念辨析 → 自测问题（附参考答案）→ 参考来源；
3. **自测**：每个页面底部的"自测问题"可以点开折叠的参考答案，用来检验自己是否真的理解了。

> 提示：直接把 HTML 文件下载到本地后用浏览器打开即可，页面不依赖任何外部资源，离线可看。

## 四、我是怎么做这个作业的（AI 使用说明）

按作业要求，如实说明 AI 的参与情况：

- **AI 参与的部分**：
  - 学习三个概念时，用 AI 工具（CodeBuddy / DeepSeek 等）查询概念解释、核心机制与权威资料来源；
  - 用 AI 辅助生成 HTML 页面的框架代码与排版样式；
  - 用 AI 辅助完成 git 仓库的创建、提交与推送操作。

- **我本人完成的部分**：
  - 确定学习主题、Skill 命名与整体结构；
  - 阅读并核对所有生成内容，删除不准确表述，补充我自己的理解（尤其是"概念辨析"和"应用案例"部分，案例都换成了广告学专业的场景）；
  - 亲手撰写自测问题，并用"折叠答案"的形式检验学习效果；
  - 在 `concept-relationship.html` 中用自己的类比（"一个广告公司里的策划总监"）重新解释三个概念的关系。

## 五、学习心得

> Agent 决定"谁来做"，上下文决定"它知道什么"，Skill 决定"它能做什么"——三者合起来，才是能真正干活的 AI。

**1. 概念理解上最大的收获**

做这个作业之前，我一直把"AI"当成一个笼统的黑盒子，现在终于能把它拆开看了。最触动我的是"上下文"这个概念——我终于搞明白为什么 AI 经常"聊着聊着就忘了"、为什么"新开一个对话它就不认识我了"：不是它笨，是它的"办公桌面"就这么大，而且下班就清桌。想通这一点之后，我用 AI 的习惯都变了：重要资料尽量放在提问的开头而不是中间，长对话到一半会先让它总结再继续，跨天的任务会主动把关键结论重新喂给它。

**2. 关于 Agent 和 Skill 的思考**

Agent 像一位对结果负责的策划总监，Skill 像团队沉淀下来的 SOP 手册。以前我以为"会用 AI"就是会写提示词，现在意识到写提示词只是"贴便签"，真正有价值的可能是把成熟的工作流程做成 Skill 沉淀下来反复使用。这对广告行业特别有启发——广告公司最依赖的恰恰是"方法论资产"（怎么调研、怎么定位、怎么写提案）。也许未来广告公司竞争力的一部分，就看谁家的 Skill 库更厚、复用效率更高。

**3. 做作业过程本身的体会**

这次作业本身就是一次"给 Agent 下达目标"的实践：我提供目标和授权，AI 助手完成了建仓库、写资料、提交推送的全过程，我负责验收和理解。我第一次真切感受到"从操作工具到验收结果"的角色转变。但这个过程也提醒我：AI 能替我执行，替不了我理解——如果老师课堂提问我答不上来，这些再漂亮的页面也只是别人的作业。所以交作业之前，我把三个概念的自测题全部合上答案重做了一遍。

**4. 下一步想做的**

打算之后把"概念学习资料生成"这个 Skill 真正用起来：遇到《广告学概论》《计算广告》里看不懂的概念，就按 SKILL.md 里的六步流程给自己生成一份资料。学一门课，攒一个自己的学习资料库——这个仓库以后就是我的"外挂大脑"的雏形。
